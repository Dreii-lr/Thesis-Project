# Document processing authentication

Uploads use `/api/v1/document-processor/parser` on the frontend origin so the
existing sign-in cookie is forwarded. The retry path
`/api/v1/document-processor/documents/:documentId/process` uses the same proxy.
Set server-side `DOCUMENT_PROCESSING_URL` to the document-processing origin
(default `http://127.0.0.1:9090`, without `/api/v1`). Restart Next.js after changing it.
Other API routes retain their existing destinations.

Document processing validates the active teacher/admin account and forwards the
request's access token to the backend catalog API. No separate service key is
required. Authentication failures require signing in and manually retrying.
